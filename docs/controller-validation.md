# 角色台阶与返程导航验证

2026-09-13。使用 Godot 4.6.3 / Jolt、60 Hz 原生物理；最终测试均直接实例化 `scripts/combatant.gd`，未修改地图几何、碰撞或 NAV。

验证控制器 SHA-256：`edf4757bb1bdd276c8ece9e16c31292c291ba1cc1d7f6c012cee88665964fae0`。

## 问题与复现证据

此前出生点 → A/B 的 20 条物理路线全部通过，但没有覆盖到站后的 A ↔ B 返程。真实游戏中的 CT 在首次抵达站点后转移，会经过 CT 坡道的一条不同路线，从而卡住。独立探针确认：买阶段等待 20 秒、角色旋转、队伍分离、到航点后停一帧或同帧继续移动，单独改变均不影响首次到站；两种方向的返程则都能稳定复现卡点。

| 路线 | 卡住时脚底 x,y,z（米） | 下一航点 | 状态 |
|---|---|---|---|
| A → B | `[-20.244, 0.082, 31.692]` | `[-20.25, 0.143, 31.25]` | 着地、速度 0、没有交战目标 |
| B → A | `[-20.260, -0.130, 29.427]` | `[-20.25, 0.0079, 29.75]` | 着地、速度 0、没有交战目标 |

源碰撞的凸边位于胶囊前缘，中线向下射线读到了凸边后方更低的坡面。按这个高度抬升不足以跨过凸边；增加更远的中线探点也仍读到低坡。碰撞并非可忽略的平地接触：A 返程测试得到近竖直法线 `(0.173, 0.066, 0.983)`；B 返程为 `(-0.239, 0, -0.971)`。法线、移动量、剩余量及每秒轨迹已保存于修复前 JSON。

小幅逐档抬升也未完全解决问题：最小可移高度在下一次移动时被 `floor_snap_length=0.4` 吸回原坡面。A 返程测试重复执行了 32 次小抬升仍未通过。

## 修复条件

保留原台阶快路径；失败后增加一次不超过 0.46 米的胶囊抬升，并同时满足以下条件：

1. 前方有合法支撑面，射线启用 `hit_from_inside`，避免从高箱内部误读为地面。
2. 向上扫掠无障碍。
3. 抬升位置的完整胶囊无重叠，检查头顶空间。
4. 从抬升位置向前扫掠无障碍。

完整阶高避免立即被吸回旧坡面。未放宽墙面法线判定，也没有修改源障碍位置。CT 爆破守点策略的调整与本次物理修复相互独立；测试明确要求 A ↔ B 仍能实际行走。

## 最终结果

返程测试使用三种航点驱动方式，但全部调用同一个最终生产控制器：到点停一帧、同帧连续跟随、实际 `main._bot_tick`。A → B、B → A 各三种，共 **6/6 通过**，到达耗时约 19.3–20.4 秒。此诊断探针使用 2.2 米站点到达范围；地图完整路线测试另行采用 0.5 米最终到达检查。

已核对地图完整测试生成的 JSON：同一控制器哈希下，20 条出生点路线加两条返程，**22/22 实际通行通过**。两条返程最终三维距离误差分别为 0.243 米、0.306 米，均符合 0.5 米到达标准。

高墙和低顶测试 **8/8 符合预期**：

| 场景 | 预期 | 实际 |
|---|---|---|
| 0.32 米台阶 | 通过 | 通过 |
| 0.46 米台阶 | 通过 | 通过 |
| 0.50 米障碍 | 保持阻挡 | 保持阻挡 |
| 0.60 米障碍 | 保持阻挡 | 保持阻挡 |
| 0.90 米障碍 | 保持阻挡 | 保持阻挡 |
| 1.80 米障碍 | 保持阻挡 | 保持阻挡 |
| 0.32 米台阶、1.85 米净高 | 头顶空间不足，阻挡 | 阻挡 |
| 0.10 米台阶、1.90 米净高 | 通过 | 通过 |

两次最终运行均退出码 0，无脚本或资源清理错误。探针已移除实验子类，只测试实际 `combatant.gd`。JSON 的 `passed` 描述是否走过障碍，`expectation_met` 描述结果是否符合场景要求，因此高墙保持阻挡是成功的回归结果。
