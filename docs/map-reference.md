# Mirage 场景：真实地图数据与卡通表面

当前运行的场景以本机 Counter-Strike 2 build **25218825** 的完整 `de_mirage` 可见几何、物件变换和物理网格建立。地图建筑、掩体、箱堆、台阶、拱门、宫殿脚手架与室内物件保持原位置与比例；表面转换为高粗糙度、顶点色与简化叶片轮廓。

早期从 NAV 轮廓推断建筑与手摆箱体的版本已退出运行场景。NAV 只用于导航，不再用于猜测建筑、地面或障碍形状。

## 数据与建模方法

- 用 Source 2 Viewer CLI 20.0 **只读**导出本机 `maps/de_mirage/world.vwrld_c`、`world_physics.vmdl_c`、地图实体及 NAV。游戏安装目录没有修改。
- 完整渲染源包含 3,524 个可见/辅助节点记录。解析 GLB 时，先按每个 primitive 的实际索引提取顶点，再应用完整节点变换；不会把材质合批的总包围盒当成单个箱子。
- 建筑、地面和实体道具保留原三角形轮廓。对源 UV/法线接缝做位置焊接，然后导出明确的硬边法线与顶点色，避免独立三角面简化造成破面。
- 源材质的基础色仅在离线转换时取样、减弱纹理噪声并压缩颜色层次。运行时不使用原版贴图、法线贴图或烘焙光照贴图。
- Ground 地面使用 96% 材质中值颜色与 4% 源采样、64 级颜色量化，减少大三角形间的跳色。最终前后 GLB 对比确认所有顶点、法线、索引和非地面颜色完全一致，只修改 26 个地面空间组的颜色；记录在 `artifacts/ground_palette_audit.json`。
- 植物、部分栅栏及贴花的透明轮廓转换为粗粒度实几何；植物轮廓还做了简化。`source_geometry_manifest.json` 逐 primitive 标记 `alpha_silhouette_applied`，明确区分源不透明几何与透明轮廓改动。
- 非可见工具体积、遮光辅助面和少量污渍贴花不显示。真实的工具桶 `bucket_tools` 保留，没有因名字含 tools 而误删。

最终视觉网格 **1,197,738 三角面、173 个空间合批组**。主要 A 点道具（弹药木架、双列罐体架、包装箱、脚手架、棚布）全部保留源三角形和原位置；没有用通用木箱替代罐体架。

源 `materials/effects/smoke/dust_002.vmat` 使用 `csgo_effects.vfx`、三层动画透明遮罩、深度羽化及不投影标志；GLB 导出器却没有给它写透明模式。将这些飘尘特效片当作普通材质会生成横跨天空的灰色矩形。已明确省略该材质的 10 个绘制单元、74 面，逐节点原因见 `source_geometry_manifest.json.excluded_shader_effects`。这不是建筑删减，物理与导航文件不变。

独立几何核验见 `docs/placement-audit.md`：1,282,397 个启用状态下的建筑、地面、道具及棚布不透明源顶点均在生成物中找到，最大误差约 **0.00000881 米**；A 点关键道具保持原顶点与三角形数。

## 尺度、出生点与爆破区

Source 单位换算为 0.0254 米，原点移动只用于让地图便于编辑：

```text
x = (source_x + 670) * 0.0254
y = (source_z + 256) * 0.0254
z = (-source_y - 847) * 0.0254
```

Source 2 Viewer 的 GLB 坐标是 `(source_y, source_z, source_x) * 0.0254`，因此还要转换为 `(glb_z + 17.018, glb_y + 6.5024, -glb_x - 21.5138)`。已用三项独立实体坐标交叉验证，误差小于 0.000009 米。

- 保存全部 **16 个 CT / 17 个 T** 原出生位置，运行时加 0.08 米落地余量。
- A 爆破区使用原触发器的斜四边形：`(1.371602,28.574994) → (10.312401,29.895793) → (10.210801,37.515792) → (1.371602,37.617393)`；不能仅用矩形包围盒判断安放。
- B 爆破区使用原四边形，平面范围约 `x=-39.268392…-30.733993, z=-32.689793…-23.342593`。
- NAV 的 3,545 枚原三角形保持原坡度与上下层高度，未把下水道和 B 小压为同一平面。

[公开雷达元数据](https://github.com/2mlml/cs2-radar-images/blob/master/de_mirage.txt)、[Source 2 Viewer 命令行说明](https://github.com/ValveResourceFormat/ValveResourceFormat/blob/master/docs/guides/command-line.md)。

## 原生碰撞与导航

从原世界与实体网格保留 **139,715 枚碰撞三角形**，按空间分为 200 个原生静态碰撞块。独立验证按正确层匹配了全部三角形，最大坐标误差约 0.000005 米。没有根据 NAV 额外生成墙、箱子、沙丘或坡面。

- Layer 1：真实固体，参与人物、子弹和视线碰撞。
- Layer 4：playerclip / passbullets，只阻挡人物移动。
- Layer 8：grenadeclip。
- 买区、爆破区、位置名称等触发体不当作实体墙。
- 读取原实体的启用状态：普通爆破模式不显示 17 个初始禁用的 Retake 封路/百叶窗残片渲染节点；38 个禁用或非固体物理形体不参与碰撞。包括 29 个 Retake 封路体、6 个 Never Solid brush、布帘和两个尚未启用的破窗残余模型，共移除 928 个源碰撞面。仍启用的窗户金属封板保留碰撞。

Godot 的原生碰撞三角形使用顺时针顺序，导出时对 glTF 反转一次索引；不使用双面碰撞来掩盖法线问题。

导航从原 NAV 的高度层取样，并用真实碰撞检查站立身体与通路。人物跨越低台阶由角色控制器处理，不能通过改造真实建筑来迁就路径。`tools/map_movement_test.gd` 必须使用实际 `combatant.gd.setup()` 和移动方法；空路径属于失败，不能算完成路线。

最终导航含 **15,044 个节点、52,682 条边**。在 Jolt、固定 60 Hz 下，实际运行双方前 5 个出生点分别到 A/B 的 20 条路线，以及抵达后的 A → B / B → A 两条巡逻路线，**共 22 条角色行走路线全部通过**。使用游戏本身的胶囊体、碰撞层、台阶方法和 `move_direction()`，没有测试专用抬升或传送。路径必须非空，完成时角色脚点距离目标必须小于 0.5 米；22 条路线的实际终点误差为 0.204–0.307 米。任一路线失败会返回进程退出码 1。

| 首个出生点 / 巡逻路线 | 路径非空 | 实际到达 | 物理帧数 | 终点距目标（米） |
|---|---|---|---|---|
| CT → A | 是 | 是 | 446 | 0.290 |
| CT → B | 是 | 是 | 850 | 0.227 |
| T → A | 是 | 是 | 875 | 0.204 |
| T → B | 是 | 是 | 1471 | 0.307 |
| A → B 巡逻 | 是 | 是 | 1240 | 0.243 |
| B → A 巡逻 | 是 | 是 | 1249 | 0.306 |

全部 33 个原出生点到两包点的 **66 条图路径均非空**。完整逐路线结果（含路径点数、帧数、终点、目标、误差、控制器 SHA256）在 `artifacts/map_routes.json`；巡逻两条的同次结果同步到 `artifacts/map_patrol_routes.json`。复现命令：`Godot_console.exe --headless --path . --script res://tools/map_movement_test.gd --fixed-fps 60`；追加 `-- --patrol-only` 可只跑 A/B 往返。

本次实际控制器 `scripts/combatant.gd` 的 SHA256：`edf4757bb1bdd276c8ece9e16c31292c291ba1cc1d7f6c012cee88665964fae0`。原 A/B 返程在 CT 坡道的卡点由真实控制器内最高 0.46 米、检查胶囊扫掠与落脚面的跨阶处理解决；没有修改 NAV 或源碰撞。

当前导航采用可步行的双向邻接，未实现 Source NAV 的单向跳落连接；因此例如 T → B 的 Bot 可能选择较长的安全绕路。图连接测试和上述 22 条物理路线不代表每一处跳跃、窗户破坏或临时动态障碍均已实现。

## 镜头与光照

高建筑保持原高度。游戏中的 `architecture.gdshader` 沿玩家朝向的整个扇面剖切：范围 42 米，扇面外缘约 166°，与视野雾的渐变外缘对齐。除检查建筑片元的地面位置，还沿正交镜头方向投影到角色地面，移除从前景挡住该扇面的高处结构。朝向每个物理帧同步，转身后离开扇面的建筑恢复；角色周围只保留 1.25 米的自遮挡清理范围。

建筑和道具在角色脚点以上 1.35 米剖开；棚布和植物的阈值为 2.2 米。Ground 地面不参与剖切，低掩体底部仍可辨认。B 点 `bomb_site_tarp` 全部 5,424 个原三角面保留。视觉剖切不修改碰撞、子弹射线、墙后敌人隐藏或导航，墙后的区域仍受逻辑视野遮挡。当前使用片元移除，没有为原空心网格新建截面封盖。

主菜单“地图预览”使用独立环绕镜头，关闭剖切和视野雾，隐藏对局角色与临时效果。支持左键旋转、右键/中键平移、滚轮缩放、正交/透视切换和五个主要点位定位；退出时还原原游戏镜头参数。此模式便于核对完整屋顶、墙面、棚布和原位物件。

本次实际 GPU 和 Jolt 验证 96 项通过，覆盖 A/B 四方向、18 米远处、扇面侧缘、前景投影遮挡、转身恢复、低掩体保留，以及真实墙体继续挡住敌人视线与人物移动。记录在 `tests/fan_view_results.json`，截图在 `artifacts/fan_view/`。

已用 Forward+ 实际渲染并目视核验 `assets/map/overview.png`、`a_site.png`、`b_site.png` 和 `b_site_cutaway.png`；B 点剖切图中可直接看见站在棚下的 CT 角色以及周围原位掩体。全图中的错误灰色飘尘平面已经消失。

本机 `light_environment` 的太阳 RGB 为 `(255,223,179)`，天空 RGB 为 `(130,205,255)`，Source angles 为 `(60,318,0)`，Godot 对应方向旋转约 `(-60,-132,0)`；原 brightness 为 3.0，bounce scale 为 1.3，sky bounce scale 为 1.5。Godot 的曝光、能量和环境光需按实际渲染调校，不能把 Source 2 的数值直接等同于本引擎。

当前没有复用 Valve 烘焙光照、逐材质穿透、玻璃破坏或全部场景动画，因此不声称与 CS2 逐像素或逐项交互一致。

## 资产与复现

- `assets/map/source_environment.glb`：当前真实布局的卡通表面场景。
- `assets/map/mirage_baked.tscn`：当前完整静态碰撞与视觉入口。
- `assets/map/source_geometry_manifest.json`：逐物件来源、索引、原/输出范围和面数。
- `assets/map/source_props.json`、`collision_manifest.json`：独立测量与核验记录。
- `assets/map/map_data.json`、`navigation.json`：实际出生、爆破多边形、位置名称与分层导航。
- `tools/build_source_map.py`：从带材质的临时源 GLB 转换顶点色与轮廓。
- `tools/bake_source_map.py`：按真实源碰撞烘焙原生场景与导航。

离线依赖 Python、NumPy、trimesh、Shapely 2.1+、SciPy、Pillow、fast-simplification 和 rtree。所有输出使用临时文件原子替换。旧 `tools/build_map.py` 是早期手工推断版本，不用于当前场景重建。
